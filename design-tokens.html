Design tokens

Your source of truth

A design token system is the one place your design decisions live. Your Figma designs, your code, and your AI tools should all use it.

What is a design token?

A design token is information associated with a human-readable name. At minimum, it is a name and value pair. For example:

color-text-primary: #000000;
font-size-heading-level-1: 44px;

Design token properties

A token name can carry more information than its value. For example:

  • Value — the color, size, or other setting itself
  • Type — what kind of value it is, such as a color or a dimension
  • Description — a note on when to use it

Tools and design systems can add more metadata to extend the format as needed.

The design token file

Design token files are JSON files. This example follows the format from the Design Tokens Community Group. It defines one color token, pure red, written as red, green, and blue values from 0 to 1:

{
  "token name": {
    "$type": "color",
    "$value": {
      "colorSpace": "srgb",
      "components": [1, 0, 0]
    }
  }
}

Figma has announced support for importing and exporting variables in this format. Check Figma's documentation for what is available on your plan.

How to use your token file

Use one file for design and code

A single token file can be used to generate CSS custom properties, Sass variables, Figma variables, and more. This keeps design and code aligned.

Build accessibility into the file

Add color pairs that you have already checked for contrast, and minimum type sizes, as tokens. Check your color pairs with the Contrast Matrix or Token Foundry before you add them. Contrast is only one part of WCAG, so this does not replace testing your finished pages.

Tell AI tools to use it

You can point Claude Code to your JSON token file and tell it to use those variables when it writes the code for your design. Then check its work yourself. AI tools can still add values that are not in your file.
