Workflow guide

A Skeptic's Guide

Your final design must conform to your design token system. This guide covers the AI tools from the talk and its two main workflows: Claude Design to Claude Code, and Figma to Claude Code. Each one keeps your design governance and human oversight in place.

Claude Design → Claude Code · Figma → Claude Code WCAG 2.1 AA Read time ~8 min

Being an AI skeptic

  • Research and learn about the limitations of AI.
  • Think about what you feel comfortable with, professionally and personally.
  • Follow your organization's AI governance.
  • Don't let AI create your first draft.
  • Be the director of your AI tool.
  • Always test and check what AI creates.
Tools

AI tools

The tools I demonstrate
Design

Claude Design

Explore and iterate on design options quickly, then hand the design off to Claude Code.

Connector

Figma MCP server

MCP stands for Model Context Protocol. The Figma MCP server connects Figma to Claude Code, so Claude Code can read your Figma designs and write to your Figma files.

Code

Claude Code

Installed on your computer and used in the terminal. Your projects are saved locally and on GitHub.

Tips

Claude Code tips

  • Use Claude Code to add your design tokens to Figma.
  • Save your favorite prompts to a text file.
  • Tell Claude Code to save your favorite specifications to a notes file, saved as a Markdown (.md) file.
  • Save every file you want Claude Code to use in your project folder. For example: APIs, design token files, and notes from previous sessions.
Step 1

Pick a workflow

The two main workflows from the talk
Workflow 1

Claude Design → Claude Code

Use this workflow when you don't have Figma or a Figma Pro account, or when you want to explore ideas first and then edit.

  1. Ask Claude Design to save the standards from your JSON file, so new designs follow them. (Claude Design calls these saved standards a “design system.”)
  2. Explore design options using Claude Design.
  3. When you are happy with your design, tell Claude Design to create a Claude Code Handoff file.
  4. Point Claude Code to your handoff file and your Design token JSON file.
  5. Constrain the design to your Design Tokens.
  6. After creating your code, check for accuracy and security.
Workflow 2

Figma → Claude Code

Use this workflow when you want to create the design in Figma and then code it in Claude Code, and you want control over the entire design process.

  1. Design in Figma (Step 2).
  2. Ensure your Figma MCP server is connected to Claude Code.
  3. Point Claude Code to your Design Tokens JSON file.
  4. Constrain the design to your Design Tokens.
  5. After creating your code, check for accuracy and security.

Note:

Before you design in Figma, your tokens should already be in Figma as Variables, imported from tokens.json rather than recreated by hand. At the time of writing that usually means a plugin that reads the Design Tokens (DTCG) JSON format; Figma has announced native import, but check whether it is available on your plan. You can also load them with Claude Code if you have MCP configured in Figma. If your Figma styles were built by hand instead of using your design token file, your standards can drift.

Step 2

Design in Figma

For Workflow 2 · You are the art director
01 Human

Sync the Variables before you start

Re-import from tokens.json at the beginning of the design session, not the end.

02 Human

Use your variables when designing. Do not type in values.

Fills, strokes, corner radii, gaps, text styles: use your variables (or design tokens) for all of these values.

If a design needs a value that has no token, make a note of it. Add it to tokens.json and re-sync. Do not add a value by hand.

03 Human

Use Auto Layout

Auto Layout is the most reliable way for the file to record intent — direction, spacing, alignment, and how things resize. It also keeps all of your spacing consistent throughout your design.

04 Human

Make sure your design specs document everything beyond what you design in Figma.

Values such as state colors and breakpoints belong in your JSON design token file. Behavior such as focus order and screen reader announcements belongs in your written specs. Some examples are: (This list may not be inclusive of everything you need to define)

  • Every interactive state — hover, focus, active, disabled, error, loading, empty
  • Focus order and keyboard behavior
  • What a screen reader should announce, and when
  • Breakpoint behavior — what reflows, what stacks, what is removed
  • Which text is real content and which is placeholder
05 Human

Audit your design

Some examples include: checking contrast on every text-and-background pairing. And checking touch targets: 44 × 44 px is a common best-practice target.

Step 3

Test and verify your code

The same for every workflow
06 AI-assisted

Ask Claude Code to check your work against your token file

Ask Claude Code to compare the code against your JSON design token file and list any colors, spacing, or type values that don't match a token.

Treat the answer as a first pass, not proof. Claude Code can miss values or describe checks it didn't fully run, so confirm its findings yourself in steps 07 to 09.

07 Human

Read and verify the code

Read the code that AI writes, and make sure it meets current standards for your platform.

08 Human

Check accessibility manually and with a tool

Automated tools miss things such as focus visibility, screen reader announcements, and reflow. These four manual checks are a starting point, not a full audit:

  • Tab through the design to verify the tab order is correct.
  • Test your design on a screen reader if possible.
  • Test your design in a mobile-sized browser.
  • Zoom into your design to 200% and check to see if anything breaks.
09 Human

Check for security vulnerabilities

Review the code for security issues before it goes to production. These guides can help:

  • OpenSSF: Security-Focused Guide for AI Code Assistant Instructions
  • OWASP Cheat Sheet Series
10 Human

Check the final design against your design file.

Does it meet the need you were originally intending?

Bonus

Bonus workflows

Not covered in the talk

These two were not part of the talk. They build on the main workflows: Workflow 3 leads into Workflow 2, and Workflow 4 combines Figma with Claude Design. Use the Step 2 Figma practices and the Step 3 checks for these too.

Workflow 3

Claude Code → Figma

Use this workflow when you have a design you already built in Claude Code and you want new design options in a similar style.

  1. Ensure your Figma MCP server is connected to Claude Code.
  2. Ask Claude Code to recreate your existing design in Figma.
  3. Check that the Figma layers use your variables, not typed-in values.
  4. Explore new design options in Figma (Step 2).
  5. When your new design is final or close to final, continue with Workflow 2.

Check Figma's documentation for which plans and seats can use the Figma MCP server.

Workflow 4

Figma → Claude Design → Claude Code

Use this workflow when your design idea is already in Figma, or when you want a new design based on a previous one, and you want to see design options quickly.

  1. In Figma, export the design frame as a PNG, and the variable list as text. You can also ask Claude Design to save the standards from your JSON file, so new designs follow them.
  2. Explore design options using Claude Design.
  3. When you are happy with your design, tell Claude Design to create a Claude Code Handoff file.
  4. Point Claude Code to your handoff file, your Figma file or a PNG of your Figma file, and your Design token JSON file.
  5. Constrain the design to your Design Tokens.
  6. After creating your code, check for accuracy and security.
