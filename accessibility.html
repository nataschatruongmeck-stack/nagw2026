Accessibility statement

How accessible this site is, and how to tell me it isn't

This site publishes tools for checking accessibility, so it should be able to account for its own. Here is what was tested, what wasn't, and what is known to be imperfect.

"Partially conformant" is the honest answer rather than a hedge: the checks below were real, but they did not cover everything Level AA requires, and no assessment that skips screen-reader testing can claim full conformance.

How it was assessed

Self-assessed. This has not been independently audited.

What was tested

  • Contrast (SC 1.4.3, 1.4.11) — every text and UI colour pair in the site's own CSS computed against the WCAG 2.1 formula. Text ranges from 6.5:1 to 17.8:1; component boundaries clear 3:1.
  • Keyboard operability (SC 2.1.1, 2.4.3, 2.4.7) — tabbed through every page in Chrome. Focus order follows reading order, every stop has a visible focus ring, no traps, and skip links move focus rather than only scrolling.
  • Reflow (SC 1.4.10) — checked at the narrowest viewport the browser allows, with every element measured against the viewport edge. Wide tables and code blocks are inside labelled, keyboard-scrollable regions.
  • Text resize (SC 1.4.4) — root font size doubled to 200%. No clipping, no overlap, no horizontal scrolling.
  • Structure (SC 1.3.1) — one h1 per page, no skipped heading levels, landmarks present, data tables carry row and column scope.
  • Motion (SC 2.3.3) — all animation is disabled under prefers-reduced-motion.

What was not tested

  • No screen reader. Nothing here has been verified with VoiceOver, NVDA, or JAWS. This is the largest gap.
  • No automated audit tool such as axe or Lighthouse.
  • One browser only — Chrome on macOS. Not tested in Safari, Firefox, or on iOS or Android.
  • No testing with disabled users.
  • Not tested in Windows High Contrast / forced-colors mode.

Known issues

Listing these is deliberate. A statement claiming no known issues usually means nobody looked.

  • Screen-reader behaviour is unverified The tools build results dynamically, and whether those updates are announced usefully has not been confirmed with any screen reader. Treat the tools as untested with assistive technology.
  • Contrast results are not a conformance verdict Both tools compute ratios for flat, opaque colour only. They ignore alpha, overlays, gradients, and imagery behind text, and they say nothing about the other Level AA criteria. Each tool states this alongside its results.
  • Wide tables need horizontal scrolling on small screens The contrast matrix and the workflow guide's tables scroll sideways below roughly 640 px. The regions are keyboard-reachable and labelled, but the data is genuinely harder to read at that size.
  • Colour is load-bearing in the matrix Results are also labelled in text (AAA, AA, AA LARGE, FAIL) and state the numeric ratio, so the information is not colour-only — but the layout does lean on colour to be read quickly.

Technical notes

Every page is a single HTML file with its CSS and JavaScript inlined. There are no third-party requests: the two fonts are served from this site. The tools run entirely in the browser — nothing you enter is transmitted anywhere.

Accessibility depends on JavaScript in both tools, since results are generated in the browser. The workflow guide and this statement are static and work without it.
