Accessibility statement

How accessible this site is

This page explains what was tested on this site, what was not tested, and the issues I know about.

Standard and scope

Standard
WCAG 2.1 Level AA
Covers
All six pages at nataschatruongmeck-stack.github.io/nagw2026/ — the home page, the design tokens page, this statement, and the three tools
Status
Partially conformant — see known issues below
Last checked
26 September 2026

The checks below did not cover everything Level AA requires. Without screen reader testing, this site cannot claim full conformance.

How it was assessed

Self-assessed. This has not been independently audited.

What was tested

  • Contrast (SC 1.4.3) — the rendered text color of every visible text element on all six pages was measured against its actual background in Chrome, using the WCAG 2.1 formula. Site text ranges from 4.79:1 to 17.84:1, and nothing falls below 4.5:1. Color swatches and previews that show your own palette in the tools were excluded, because those colors are data you enter.
  • Focus visibility and order (SC 2.4.3, 2.4.7) — every focusable element on every page (up to 159 in Token Foundry, depending on the tab, and 7–23 on the others) was focused in source order in Chrome, and each one showed a visible focus indicator. No page uses a positive tabindex, so focus order follows source order. Each page's skip link moves focus to the main content.
  • Reflow (SC 1.4.10) — every page, and every tab in Token Foundry, was loaded in a 320 px-wide frame and every element was measured against the viewport edge. No page scrolls sideways. Wide tables and code blocks sit inside labeled, keyboard-focusable scroll regions.
  • Zoom (SC 1.4.4) — checked as the layout equivalent of 200% browser zoom on a 1280 px screen (a 640 px-wide frame). No sideways scrolling, and Token Foundry's export panel stays available.
  • Structure and names (SC 1.3.1, 4.1.2) — one h1 per page, no skipped heading levels, landmarks present, data tables carry header scope, no duplicate IDs, and every visible form field and button has an accessible name.
  • Motion (SC 2.3.3) — every page has a prefers-reduced-motion rule that turns off its animation and transitions.

Fixed during the 26 September 2026 check

  • Token Foundry hid its export panel (JSON, Copy and Download) on screens narrower than 1100 px, which included 200% zoom on most laptops. It also forced sideways scrolling at 320 px. It now stacks into one column.
  • Token Foundry form fields in the color pair cards, the Motion tab, the base font size and the component preview had no accessible name, and several remove (×) buttons had only the × symbol as their name. All now have names.
  • Token Foundry's looping "live" indicator kept animating under prefers-reduced-motion. It now stops.
  • The contrast matrix scroll regions in both tools could not be reached by keyboard. They are now focusable and labeled.
  • The accessibility-page link in the workflow guide's dark footer was 2.1:1. It is now 8.3:1.
  • On narrow screens, the site navigation hid some links off-screen in a strip that scrolled sideways. The links now wrap onto a second line, and the bar no longer stays pinned to the top on small screens.

What was not tested

  • No screen reader. Nothing here has been verified with VoiceOver, NVDA, or JAWS. This is the largest gap.
  • No manual Tab-key walkthrough on this date. Focus was moved to each element by script, which confirms focus rings and order but does not prove there are no keyboard traps. A hands-on keyboard pass is still worth doing.
  • No text-only zoom test. Much of the site's text is sized in pixels, so it scales with browser zoom but not with a browser's text-size-only setting.
  • No automated audit tool such as axe or Lighthouse. The checks above were scripted by hand in Chrome.
  • One browser only — Chrome on macOS. Not tested in Safari, Firefox, or on iOS or Android.
  • No testing with disabled users.
  • Not tested in Windows High Contrast / forced-colors mode.

Known issues

These are the issues I know about.

  • Screen-reader behavior is unverified The tools build results dynamically, and whether those updates are announced usefully has not been confirmed with any screen reader. Treat the tools as untested with assistive technology.
  • Contrast results are not a conformance verdict Both tools compute ratios for flat, opaque color only. They ignore alpha, overlays, gradients, and imagery behind text, and they say nothing about the other Level AA criteria. Each tool states this alongside its results.
  • Wide tables need horizontal scrolling on small screens The contrast matrices in both tools scroll sideways inside their own regions on narrow screens. The regions are keyboard-reachable and labeled, but the data is genuinely harder to read at that size.
  • Color is load-bearing in the matrix Results are also labeled in text (AAA, AA, AA LARGE, FAIL) and state the numeric ratio, so the information is not color-only — but the layout does lean on color to be read quickly.

Technical notes

Every page is a single HTML file with its CSS and JavaScript inlined. The two site fonts are served from this site. The tools run in the browser and do not send what you enter to any server, with one exception: if you choose a Google Font to preview in Token Foundry, the font name is sent to Google Fonts (fonts.googleapis.com) to load it.

Accessibility depends on JavaScript in both tools, since results are generated in the browser. The design tokens page, the workflow guide, and this statement are static and work without it.
